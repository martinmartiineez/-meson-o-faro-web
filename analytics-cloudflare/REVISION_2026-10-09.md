## Fallos corregidos en esta revisión

- Wrangler priorizaba wrangler.json frente a wrangler.jsonc. El primero apuntaba a dist, aunque las pruebas comprobaban dist/public. Esto rompía las rutas esperadas y exponía una segunda ruta /public/admin.html fuera de la protección. Una sola configuración, directorio público correcto y prueba de las rutas privadas e internas.
- Nombre D1 discrepante entre configuración, comandos y documentación. Unificado como mesonofaro-analytics, conservando un UUID provisional y sin tocar una base remota.
- Dos constructores y dos esquemas iniciales. El constructor alternativo delega al principal y la segunda migración queda como marcador compatible, sin recrear el esquema.
- Rutas alternativas y codificadas del editor anterior. Todas pasan por Access; también se limita el intento de acceso anónimo al editor.
- IP IPv6 malformadas y representaciones distintas de una misma IP. Validación estricta y normalización; se impide bloquear la IP administradora incluso con otra representación.
- Cookie Access malformada causaba excepción antes de validar el token. Ahora se deniega de forma controlada. Caché de claves separada por emisor y caducidad validada como número.
- Retirada en otra pestaña y rechazo durante una aceptación pendiente podían permitir seguimiento posterior. Sincronización de preferencias y descarte de aceptaciones que ya no corresponden a la decisión vigente.
- La repetición del consentimiento extendía la caducidad del mismo UUID. La aceptación repetida ya no renueva ese identificador.
- CSV escribía secuencias literales en lugar de BOM y saltos de línea. Exportación real comprobada; mantiene neutralización de fórmulas.
- Filtros diarios mezclaban UTC con días de Madrid. Los eventos se filtran por límites UTC calculados para Europe/Madrid, respetando el horario estacional; se rechazan fechas imposibles.
- Lectura de cuerpos sin límite durante el consumo. Se detiene al superar 6000 bytes, aunque falte Content-Length.
- Validadores HTTP originales no correspondían al HTML transformado. Se eliminan al inyectar el cliente; HEAD no se transforma.

## Verificación realizada

1. 22 pruebas automatizadas superadas, de sintaxis, preservación de HTML, bloqueo de rutas privadas, consentimiento y rechazo de terceros.
2. Integración con SQLite real: aplicar todas las migraciones, aceptación/eventos/retirada, caducidad no renovada, límite HTML, incidencias, exportación/supresión, configuración y limpieza.
3. Tokens RSA generados solo para pruebas: acceso válido, firma inválida, correo no permitido, emisor/audiencia incorrectos y token caducado.
4. DOM con jsdom: rechazo sin eventos ni sesión, aceptación, retirada entre pestañas, rechazo mientras espera la red y exportación CSV con BOM, saltos reales y neutralización de fórmulas.
5. Migraciones mediante Wrangler con --local; ninguna operación sobre D1 remoto.
6. Empaquetado mediante wrangler deploy --dry-run; no se ejecutó despliegue.
7. Worker en runtime local real: cinco páginas públicas, siete rutas privadas y cuatro rutas internas; ciclo aceptación/evento/retirada. Scripts internos y /public/admin.html responden 404. En este entorno fue necesario un ajuste temporal a la detección de interfaces de red, ajeno al repositorio y al Worker.
8. No se completó revisión visual en Chromium: el navegador no estaba instalado y su descarga no produjo un archivo válido. jsdom y el runtime local comprueban comportamiento; no acreditan diseño visual ni servicios externos reales.

Para reproducir: en analytics-cloudflare, npm ci, npm test, npm run build y npx wrangler deploy --dry-run. Para el runtime local, crear .dev.vars con un LOG_HMAC_SECRET solo de prueba y ejecutar npm run smoke:local. Este script aplica únicamente migraciones locales, levanta un runtime temporal, comprueba rutas y consentimiento y lo detiene.
